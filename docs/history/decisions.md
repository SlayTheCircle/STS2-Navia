# 事件与世界线方案取舍

本页提炼 2026-09-29 的事件／世界线调查与后续修正。原始方案和失败原因保留为技术背景；当前接线见[事件实现](../dev/events.md)与[世界线实现](../dev/worldline.md)。

## 初始化器与补丁通道

调查确认游戏加载器对无 ModInitializer 的程序集自动 PatchAll，于是早期方案误判本模组已经获得自动补丁应用。实际 ModEntry 自始带初始化器，加载器只调用 Init，五个原版追加选项因此未生效。

修正是在 Init 完成注册后显式调用 Harmony.PatchAll。此事件说明：核对上游机制后还要核对本项目的具体状态。发现补丁类、编译通过或看到新事件注册，都不能证明追加选项已执行。

## 会徽升级的替代方案

早期方案读取 AncientStats 中的欧罗巴斯相遇记录，在新局切换初始遗物。该方案把“以前遇见过先古”当成“本次获得升级”，导致已有相遇记录的档案开局直接携带野蔷薇。

游戏的欧罗巴斯之触已有获取时替换初始遗物的机制；RitsuLib 提供升级映射注入口。最终保持 StartingRelics 恒为会徽，将替换关系注册到遗物上。此方案沿用获取语义，避免自建持久化或历史记录迁移。

古老牙齿同样通过初始卡的先古化映射接入。已有游戏机制适用时，应先核对对应 API 和扩展属性，再决定是否引入自定义状态。

## 第一章与角色可用性

原案将第一章描述为“解锁娜维娅”。实施时选择角色安装后直接可选，第一章在完成一局后揭示剧情。该选择避免贡献者和新玩家先用其他角色通关才能体验模组；后续章节仍承担内容池门控。

章节条件和图像映射可调整，但变更必须同时核对揭示、奖励 UI 与池过滤，不能只改叙述文本。

## 纪元图路径与叙事接线

纪元立绘按引擎推导走全局 images/timeline/epoch_portraits/ 路径，当前未沿普通 Mod 资源重定向。因此打包器为 assets/global/ 保留全局命名空间；移动到模组前缀会使推导路径失效。

先古对话由 RitsuLib 读取 ancients 表并组装，叙述内容与解析键结构分别维护。参考 Mod 可以证明某种接线已有实践，不能替代对本项目键族、角色 Entry 和实际加载状态的核对。
