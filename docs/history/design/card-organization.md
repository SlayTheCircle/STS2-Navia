# 卡牌目录组织

评估与实施时间：2026-09-30。该方案已采纳并完成路径迁移。分类依据 CardType／CardRarity 与[工程规范](../../dev/style.md)，源码移动保留原有类型身份和运行资源关系。

每张卡已经独立成类；此次收纳改善目录导航。目录组织本身不改变依赖、状态或模块接口，共享机制的职责与解耦仍按工程规范维护。

## 分类方案比较

| 方案 | 优点 | 代价／适用场景 |
|---|---|---|
| 类型 → 稀有度 | 先按行为角色找卡，层次稳定且归属明确；调整稀有度只影响同一类型内部位置 | 同稀有度的平衡审查跨三个分支；类型分类不保证共用同一机制 |
| 稀有度 → 类型 | 便于集中查看同档强度、掉落层级和稀有度平衡 | 稀有度调整会跨一级模块移动；同类攻击、技能或能力分散在多处 |
| 机制家族 → 类型 | 便于围绕装填、礼炮、摩拉、支援查相关内容 | 多机制卡需人为选主归属，容易反复讨论；文件位置不能表达全部关联 |
| 只分类型 | 简单，直属内容降至 35／37／19 | 攻击和技能目录仍有较多平铺文件，扩充后还需进一步收纳 |

稀有度和类型都是有明确游戏含义的分类字段，适合作为内容目录依据。稀有度更偏向获取层级与平衡，类型更偏向卡的基本行为角色，因此日常实现导航优先类型，同档平衡可通过公开卡表或搜索完成。若团队的主要工作变为按稀有度做整批平衡，稀有度优先也有合理性。

机制关联适合在设计与实现索引中表达。军火流通和乘胜追击同时关联装填／礼炮，军火大亨同时关联装填／支援，铸剑为犁同时关联礼炮 token／支援。当前没有足够明确的独立卡牌机制模块来消除这些多重归属，不建议仅为收纳强行指定机制目录。

## 已采用的结构

普通池 82 张按“类型 → 稀有度”收纳；特殊用途的初始、先古与 token 单独保持一层。保留基类在 Cards 根目录，不生成空目录。

```text
Cards/
├── NaviaCardBase.cs
├── Basic/                  # 4：初始牌型
├── Ancient/                # 3：先古卡
├── Tokens/                 # 2：金花礼炮、闪耀摩拉
├── Attacks/
│   ├── Common/             # 12
│   ├── Uncommon/           # 14
│   └── Rare/               # 4
├── Skills/
│   ├── Common/             # 8
│   ├── Uncommon/           # 17
│   └── Rare/               # 9
└── Powers/
    ├── Uncommon/           # 5
    └── Rare/               # 13
```

最大叶目录为 17 张卡，共 11 个有内容的叶目录。初始／先古／token 的角色获取或生成用途值得集中导航；每类当前只有少量文件，继续按类型拆会产生一两个文件的目录。Cards/Powers 中是能力卡，与 Content/Powers 中的状态模型区分。

此结构基于实施时规模，不要求每层永久不变。分类按实际 CardType 与 CardRarity，不按中文卡名或效果中的“伤害／格挡”推断；例如技能卡可以造成伤害，能力卡也可能具有立即效果。目录不参与注册或运行时判定。

## 路径迁移与后续维护

1. 全部 91 个模型按构造参数形成迁移清单，各卡唯一归属；特殊目录对应 Basic、Ancient、Token。根目录保留基类。
2. 四项卡牌枚举已改为递归。占位符审计对找不到对应类的卡牌文本报告错误，避免因扫描缺失而静默跳过；重复卡牌类也报告错误。
3. 迁移保留类名、命名空间、注册特性、复合 ID、资源命名与模型行为。需要统一命名空间时另行核对类型发现与存档兼容，不把它隐含在目录整理中。
4. 当前文档路径随迁移更新。历史审计保留调查时旧路径／行号；可按类名递归定位当前文件，如运行 `rg --files src/STS2-Navia/Content/Cards`。
5. 素材仍按类名保留在 images/cards/，不跟随 C# 分类目录拆分；NaviaCardBase 依据 GetType().Name 拼资源路径。SDK 项目使用默认递归 Compile 包含，无需手工添加每张卡。
6. 后续移动或新增内容须核对公开花名册、本地化、动态变量、资源枚举与实际编译输入，并按影响范围验收；结合编译与实际游戏行为确认。

这些配套项适用于任一目录方案；当前扫描限制见[架构](../../dev/architecture.md)，原始卡表见[设计索引](README.md)。
