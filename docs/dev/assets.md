# 素材规范

## 跟踪与来源

母版与图像由组织私有美术仓管理，本地克隆经 `ART_SOURCE_DIR` 接入。文本 .tscn、.tres、.gd 和素材导入工程配置可随源码维护。PNG、母版、音视频、字体、编译纹理、导入缓存与侧车是本地输入或产物。美术适用授权见 [许可范围](../../LICENSING.md)。

源码采用 MIT，素材的具体权利与分发仍单独确认，见 [许可范围](../../LICENSING.md)。完整包中的多媒体不因附带 LICENSE 而自动采用 MIT。

素材母版由 ART_SOURCE_DIR 定位，实际本机目录由私有导航维护。[prep-art](../../scripts/prep-art.sh)协调裁切、命名和派生；母版映射与各类生成职责位于 [scripts/art](../../scripts/art/)，assets 中的成品用于 Godot 导入和打包。普通 DLL 编译不要求美术；完整包构建要求全部资源存在。

## 接入与验收

1. 对照母版、素材映射、代码和当前画面核对，不仅依赖旧需求单。
2. 补齐映射与派生逻辑，再生成素材。只覆盖生成文件可能在重跑时丢失。全量再生成要求所有已映射母版与角色／剧情输入齐全；缺件时在写入前失败，不以已有成品掩盖缺失。脚本保留已有输出与导入侧车，按字节更新生成结果；不清空资源目录，也不以母版 mtime 或成品已存在为理由跳过更新。未使用的旧资源需单独核对消费方再清理。
3. 输出剥离元数据并按字节比较，相同内容不替换；不得只依赖 mtime 判断母版变化。
4. 运行完整素材检查、构建与 PCK 验证，然后实测对应图窗、资源槽和动态效果。

能量主图母版当前为单张透明金玫瑰，费用图标与战斗能量计共用；独立图层按实际交付文件确认。能量计使用原版 NEnergyCounter，供齐 Label、Layers、RotationLayers、EnergyVfxBack、EnergyVfxFront 节点。纹理在旋转层中显示，耗尽变暗与数值更新由原版驱动；两侧粒子容器提供有效的粒子数组，获得能量时播放金色粒子。PCK 验证检查纹理与场景资源，游戏内验收检查 C# 生命周期与实际动效。

当前缺件与接线、验收状态由 STATUS 维护；公开的[美术贡献需求](../design/artwork.md)说明资源规格与贡献方式。母版位于组织私有美术仓，本地经 `ART_SOURCE_DIR` 定位。占位图满足资源存在性时，仍需明确其美术状态。

## 角色骨骼资源

战斗角色的目标路线为 Godot 原生骨骼／节点动画。刚性部件可用 Sprite2D 与节点层级，柔性发束和裙摆按需使用 Skeleton2D、Bone2D、Polygon2D；动画由 AnimationPlayer 等原生资源驱动。用脚本生成、校准和渲染场景，不将编辑器 GUI 操作作为可复现构建的前提。造型与阶段验收规则见[美术需求](../design/artwork.md#局内角色骨骼动画)。

母版、拆件 PNG、补画候选及生成来源记录保持私有，通过 ART_SOURCE_DIR 接入；文本场景、原创组装脚本和动画接线可随源码维护。局部坐标、枢轴、绘制顺序和零件身份应有明确映射，避免每次重新生成图片后依赖人工摆放。imagegen 用于图像素材，网格、权重和骨骼数据由组装工具生成并验证。

原生场景在标准 Godot 中验证加载与渲染，在游戏中验证动画触发和生命周期。接入时核对对应版本 RitsuLib 的非 Spine 状态机与 AnimationPlayer 后端，覆盖 Attack、Cast、PowerUp、Hit、Idle 等触发，并验证死亡、复活、低血量、翻转与打断；旧四态换图驱动迁移时避免重复触发。具体实现和验证进度只由 STATUS 维护。

## 图标实尺寸检查

运行 `python3 scripts/art_review/preview.py --output local_dev/art-review` 生成自包含 HTML 与 JSON 清单；可用 `--before` 指向带分类子目录的旧图目录，`--review` 传入按 `folder/stem` 索引、值含 `status`／`note` 的判断 JSON。输出留在忽略目录，不进入游戏包。

基准取自支持版本的原版场景逻辑像素：Power 40、遗物／药水 60、支援徽记 35、卡面费用 64；内联费用使用本项目 24px 派生规格。页面提供明暗底、压力缩小、放大、描边及修改前对照，不模拟游戏着色器、数字遮挡、UI 缩放和悬停大图。

确认的 Power 派生修饰集中在 `scripts/art/icon-finishing.sh`，先在临时目录完成再按字节写成品，避免中间图造成重复生成时的 mtime 变化。现有装填家族使用细深金描边，其余图标不批量调整。能量柔光纹理由 `scripts/art/energy.sh` 程序生成；战斗光晕放入原版耗尽变暗的 Layers，粒子沿用原版获得能量时的触发点。

### 原生角色生成与验证

`scripts/art/character-rig.sh` 从母版的 `角色骨骼/godot/运行素材/` 复制已选图集；`tools/character_rig/` 保存 UV 分区、权重与动画定义，`build-pck.sh` 导入纹理后生成 `scenes/characters/rig/navia_combat.tscn`。生成器固定资源 ID、按字节更新，相同输入保留场景 mtime。腿部采用单独补画的四块刚性素材，通过两条 `Skeleton2D → Bone2D（大腿）→ Bone2D（小腿与整靴）` 链驱动；运行中只改变骨骼旋转与位置，固定素材尺寸、UV、骨长和不透明度，不对腿部做顶点变形或站姿／跪姿贴图切换。大腿、小腿在膝端裁去重叠圆头，由取样自同一图集的独立关节面连接，并随弯曲增加局部折痕；身体与裙布仍由各自驱动处理。运行脚本与生成器分离，静态录像不入游戏包。

`verify-pck.sh` 同时执行原生角色场景检查：从真实 PCK 加载并实例化，核对九段动画、关键时间、死亡／复活衔接与网格／层级复位，并用两个角色实例保护材质隔离。腿部在 201 个下蹲进度上检查四个素材变换的等距性、无剪切、固定 UV／骨长、支撑脚的地面约束与支撑小腿参与运动，以及复活／待机的骨骼复位；形变质量结合几何检查与逐帧目视审查确认。角色内部绘制顺序只由同级节点顺序控制，所有 CanvasItem 保持 `z_index = 0`，避免越过战斗房间的奖励／地图界面。游戏 C# 生命周期、实际接线和最终画面由对应版本试玩确认。

可选的实际渲染回归由 `tools/character_rig/validation/canvas.gd` 执行，需要可用图形环境与真实渲染后端。它先确认角色确实可见，再把角色置于原版战斗场景的 -10 层，覆盖奖励／地图所在的前景层；检查动作过程中无角色像素越过前景，并确认祖先透明度可隐藏角色。使用 `NAVIA_MOD_PCK` 指定候选包；此项检查使用真实图形后端。
