# 文档职责与仓库边界

## 模块与权威来源

| 位置 | 职责 |
|---|---|
| 根 README／CONTRIBUTING | 安装、开发起步与协作入口 |
| STATUS／CHANGELOG | 当前能力和限制／用户可感知的版本变化 |
| docs/design/ | 原始设计、卡表、参考升级、实现差异与美术贡献需求 |
| docs/dev/ | 当前架构、各内容模块规则、环境、素材、验证与交付契约 |
| docs/history/ | 有参考价值的技术案例、方案取舍和带日期的审计快照 |
| local_dev/ | 整个目录被忽略：本机地图、私人沟通、未整理原件、草稿、沙盒与执行归档 |

公开文档应足以让 Fork 贡献者理解设计和实现、配置自己的依赖并执行公开检查。当前运行行为以源码与本地化为依据；已知状态由 STATUS 维护；原案和历史报告注明其适用版本，不替代当前契约。

## 从私有材料提取公开内容

有助于理解意图、扩展功能、排错或避免重复试错的内容尽可能公开，包括失败方案、复核驳回理由、设计调整及验证不足。逐段判断内容价值；不因材料来自内部开发或已有过时部分而整类设为私有。

local_dev/ 始终整体私有，禁止为任何子文件增加 Git 跟踪例外。有公开价值的内容须提取、整理到对应 docs 模块；保留原件供维护者回溯。公开整理不能依赖读取本机原件，也不需要公开原件所在的内部子路径。

处理混合材料时：

1. 保留技术条件、证据、根因、取舍和可复现步骤。
2. 删除私人沟通、个人化评价、联系方式、本机真实路径、会话编号和无参考价值的操作流水。
3. 区分当前规则、历史事实、待确认设计与未验证推论；注明调查时间与版本范围。
4. 更新公开索引、实际使用方与审计输入，消除对私有原件的强依赖。

原始试玩日志可提取去除个人信息的诊断片段。署名按已确认的公开身份保留；聊天昵称或私人原话不自动成为公开署名。

## 本机导航与资源

公开文档仅导航到可选的私有入口 `local_dev/README.md`，由该入口进一步指向真实工作区与配置。缺少此入口不影响理解公开契约。公开链接不指向其他 local_dev 子文件；路径示例使用通用占位值。

游戏源码、游戏编译引用、依赖包和工具二进制由贡献者自行准备。多媒体在最终定版前不进入 Git / LFS；素材分发与授权另行决定。运行时的 res:// 资源标识、公开 API 名称、模组 ID 和已确认署名可以保留。

## 维护方式

本项目文档以中文为主，README 中英同步。每个模块有 README 入口，普通文件使用小写与连字符；文本 UTF-8 / LF、Markdown 自然换行、仓库相对链接。

新规则写进拥有该主题的文档。只有形成独立职责时才新建文件；其他页面链接到权威来源，避免复制可变清单。行为、字段、版本或资源路径变化时同步更新文档与脚本；查找旧术语、链接和配置键后交付。

当前没有其他项目的 self-docs 副本同步、机器人评审或签名服务，不将其写成已配置流程。具体交付规则见[工作流](workflow.md)。
