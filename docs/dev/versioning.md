# 版本与兼容约定

## 游戏版本支持政策

官方稳定版和 Beta 版是两条独立分支，每条分支只保留并维护各自的最新版本，不提供旧版 LTS。新版本发布后，所在分支的旧版本不再由官方提供下载，也不属于本仓库的支持目标。

例如 0.113.1 发布后，不再为 0.113.0 用户维护兼容版本。当前开发、验收与发布永远跟随目标分支最新版；若同时覆盖稳定版和 Beta 版，分别使用各自最新版并分别验收，而不是保留两条分支的旧版本。

旧引用、条件编译、兼容垫片、双目标 Loader 和历史发行包只是过渡实现或历史资产，不构成向后兼容承诺。不得为了保住已退役目标而新增适配层、延长维护周期或阻塞最新版本升级；后续收敛管线时应移除不再需要的旧目标。只有实际编译并验收的版本才能列入当次发布支持范围。

[STATUS](../../STATUS.md) 和其他历史文档中的旧版本信息只记录当时的构建、验收或发布事实，不代表持续支持。历史发行包保持原样，不回溯改号或改写当时的验收结论。

## 模组版本与发行标注

[STS2-Navia.json](../../STS2-Navia.json) 的 version 是模组版本唯一来源。完整构建经 `scripts/build_support/manifest.py` 生成安装清单；新生成发行 ZIP 从模组 version 命名，包内清单、发布说明和 tag 使用同一版本。正式版本确定由维护者决定。完整构建按 `GAME_REFS_DIR/release_info.json` 的实际版本写入 `min_game_version`，打包时核对各变体清单；根清单只表示当前分支变体的共同下限，不用 compat 名称代替实际游戏版本。

模组版本与游戏版本独立维护。RITSULIB_TARGET 选择与游戏 API 相容的 RitsuLib compat 版本，不是旧游戏支持承诺，也不一定等于实际游戏完整版本。当前编译、试玩与发行状态由 [STATUS](../../STATUS.md) 维护；游戏／依赖升级涉及钩子、注册、资源、存档或部署变化时，发布说明列出影响和必要操作。

版本采用三段式；开发候选和预发布标识是否被游戏加载器与版本比较正确消费，需要先验证后启用。不因建立规范而自动修改清单版本。历史包文件名与清单不一致作为内部遗留记录，由私有索引保存。

发布 tag 使用 v 前缀，清单不带 v。打 tag 前冻结版本与验收范围，不覆盖已公开 tag 或发行包。过渡期内若仍发布多个变体，每个变体都必须分别编译和验收，但这不产生持续维护旧版的义务。

每次新发布应明确记录实际编译与验收的游戏完整版本（含 Patch）及 RitsuLib compat。包内清单的 `min_game_version`、GitHub Release 和工坊更新说明应标注本次实际支持的最低游戏版本；该值必须与实际验收范围一致，不得直接照搬 compat 名称或旧变体共同下限。只修改字段不能证明兼容，高于该值的后续游戏版本仍需按最新版本政策重新验收。
